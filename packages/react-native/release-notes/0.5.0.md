## @umber-style/react-native@0.5.0

Animations and transitions on React Native: the `animation*` and `transition*` keys of a style, written as for the web, run through react-native-reanimated from an entry of their own, turned on by an option.
([#43](https://github.com/soroush-tech/umber-style/issues/43))

### Added

- **`@umber-style/react-native/animated`**, an entry that exports **`animated`**, and the option **`animated`** of `createStyle(theme, { animated })` and `configure({ animated })`. With it, a name of `keyframes` runs from its steps (one rule of the library for each name), times, the named easings and `cubic-bezier()` and `steps()` text are read into the library's forms, the `animation` and `transition` shorthands are expanded as CSS expands them, and a value the library would reject is dropped with a development warning, as the web drops it. A styled component is rendered as the library's animated component only when its styles animate; one that does not is the component it was. A `transition` with a state key animates the change: a `Pressable` whose styles animate and name `pressed` keeps the press from `onPressIn` and `onPressOut`, so that its style stays a list the library reads. While the system asks for reduced motion no animation starts (a finite one that fills forwards shows its last step) and no transition runs.
  ([#43](https://github.com/soroush-tech/umber-style/issues/43))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react-native.md#animations)
- **`NativeMotionStyle`**: the animation and transition keys in `NativeStyleObject`, so that a style, and a style shared with the web, writes them without a cast.
  ([#43](https://github.com/soroush-tech/umber-style/issues/43))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react-native.md#an-example-1)
- **`AnimatedDriver`**, **`Motion`** and **`MotionContext`**: the types of the value `animated` and of what the binding calls on it.
  ([#43](https://github.com/soroush-tech/umber-style/issues/43))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/options.md#binding-options)

### Changed

- Without the animated entry, an `animation*` or `transition*` key is dropped with a development warning that says the entry is not on and how to turn it on (`import { animated } from '@umber-style/react-native/animated'`, then `createStyle(theme, { animated })` or `configure({ animated })`). It said that animations do not run on React Native yet.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react-native.md#development-warnings)
- The development warning about the options of `createStyle` and `configure` that React Native does not use ends with `Only theme, remBase, lengthKeys and animated are read.` (it named three).

### Packaging

- Depends on `@umber-style/core` `^0.5.0` (it was `^0.4.0`).
- Optional peer dependencies, read only by the animated entry: `react-native-reanimated` `~4.7.0 || ~4.8.0` and `react-native-worklets` `~0.13.0 || ~0.14.0` (4.7 needs React Native 0.86 to 0.88, 4.8 needs 0.87 to 0.89; Expo Go for SDK 58 carries 4.7.1 and 0.13.0). Without the entry nothing of them, or of the entry, is loaded, and the binding keeps its range of `react-native` (`>=0.76.0`).
