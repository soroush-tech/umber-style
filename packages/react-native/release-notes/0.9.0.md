## @umber-style/react-native@0.9.0

Released for the version that every package of the family carries; `css()` given a function says what to use instead; a styled component takes a handle of a sheet made from a function of the theme and follows the window for it, and `SheetStyleProp<S>` types a style prop of entries only; `withTheme` and `withStyle` give a class component the theme and the entries of a sheet.
([#85](https://github.com/soroush-tech/umber-style/issues/85), [#87](https://github.com/soroush-tech/umber-style/issues/87), [#88](https://github.com/soroush-tech/umber-style/issues/88), [#89](https://github.com/soroush-tech/umber-style/issues/89), [#93](https://github.com/soroush-tech/umber-style/issues/93))

### Added

- **`style={sheet.card}`: a handle of a sheet made from a function of the theme.** Each name of `StyleSheet.create((theme) => ...)` is a handle. A styled component given one in `style` renders through a small inner component that reads the providers and subscribes to the window and the color scheme as `useStyle` does, and gets the registered style object `useStyle(sheet).card` gives: a sheet with `when()`, media or `whenScheme()` keys follows a rotation. A component given no handle is unchanged.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react-native.md#handles-of-a-sheet-of-the-theme)
- **`SheetStyleProp<S extends ViewStyle | TextStyle | ImageStyle = ViewStyle>`** - the type of a `style` prop that takes sheet entries only: an entry of the binding, a handle, `false`, `null`, `undefined` and nested lists. A plain object and a style of the platform's own `StyleSheet.create` are type errors; `StyleProp` still takes them.
  ([#89](https://github.com/soroush-tech/umber-style/issues/89))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#sheet-entries-only)
- **`NativeSheetEntry`** and **`NativeSheetMark`** (types) - an entry of a sheet of the binding: a native style with a mark that exists for the compiler only.
  ([#89](https://github.com/soroush-tech/umber-style/issues/89))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#sheet-entries-only)
- **`withTheme`** and **`withStyle`** - the class-component twins of `useTheme` and `useStyle`, as on the web. `withTheme(Card)` renders `Card` with `theme` set to `useTheme()` (lengths as numbers), and `withStyle(sheet)(Card)` with `styles` set to `useStyle(sheet)`, called in the wrapper's render: the same registered style objects, which follow the providers, a rotation of the window and the system color scheme as the hook does. The wrapper takes the props of the component without `theme` (or `styles`), forwards `ref`, keeps the statics that are not React's own, and is named `withTheme(Card)` or `withStyle(Card)`; the types are those of the web binding (`WrappedComponent`, `StyleWrapper`, `PropsTaking`).
  ([#93](https://github.com/soroush-tech/umber-style/issues/93))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react-native.md#class-components-withtheme-and-withstyle)

### Changed

- **`css()` given a function says what to use instead.** A function given to `css()`, as an argument (alone or in a list) or as an interpolation of its template, threw a `TypeError` that said only that `css()` has no props. It now throws one message on every path and in every binding, which names `css` and the two things that take a function:
  `css(): a function is not a style here, as an argument or as an interpolation: css() makes a class with no component, so it has no props or theme to call it with. For a value of the props, use a styled component's style function; for a value of the theme, give an entry of StyleSheet.create((theme) => ...) to the style prop.`
  With `css` of the default style the error comes at the first use of the value, as before; with `css` of `createStyle()` it comes at the call. `css()` with no function in it is unchanged.
  ([#87](https://github.com/soroush-tech/umber-style/issues/87))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)
- **`sheet.card` of a sheet made from a function of the theme is a handle.** It was `undefined`, and a type error; it is now typed `ThemedEntry`, and a misspelt name is still a type error. The type tests that asserted the error were changed to assert the handle. Names that frameworks and serializers read on any object are not handles: the sheet's own members, the members of every object, `then`, `toJSON`, `$$typeof` and names that start with `__`.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **A handle where no theme is known is a `TypeError`, in every build:** `apply`, `css()`, the styles of `styled`, a plain `View` (it reads the keys of its `style`), and a serializer (`JSON.stringify`). The message names the place and the fix, for example `apply(): an entry of a sheet made from a function of the theme (StyleSheet.create((theme) => ...)) has no theme here. Give it to the style prop of a styled component, which resolves it with its theme, or read the entry from useStyle(sheet) first.`
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **The entries of `StyleSheet.create` and `useStyle` are typed `NativeSheetEntry`**, a `NativeStyleObject` with a mark for the compiler, where they were `NativeStyleObject`; they are still assignable to it. The type tests that compared them with `NativeStyleObject` were changed. `apply` and `css()` keep their types.
  ([#89](https://github.com/soroush-tech/umber-style/issues/89))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#sheet-entries-only)
