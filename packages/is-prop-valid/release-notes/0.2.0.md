## @umber-style/is-prop-valid@0.2.0

First release, at the version of the rest of the family. Whether a prop is one that an element takes, for a `shouldForwardProp` that keeps the props of a component off the element: one function for each platform, with no dependency and no DOM access.
([#56](https://github.com/soroush-tech/umber-style/issues/56))

### Added

- **`@umber-style/is-prop-valid/react`** (the default export): true for the attributes of HTML and SVG under the names React gives them (`tabIndex`, `htmlFor`, `className`, `strokeWidth`), `data-*` and `aria-*` in any case, `x-*`, event handlers (`on` followed by any character whose code is below 91: `onClick`, and also `on-click`, `on1`) and React's own props (`children`, `ref`, `key`, `style`, `dangerouslySetInnerHTML`, `defaultValue`, `suppressHydrationWarning`). False for `as`, `theme` and the props of a component. It is true for every key of the props of the built-in elements in React's type definitions but `as`, and for every name that the predicate apps use today is true for. The React binding uses it as the default filter of a string tag.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/prop-filters.md#react)
- **`@umber-style/is-prop-valid/vue`** (the default export): the same attributes as Vue writes them: the HTML form (`tabindex`, `for`, `class`, `readonly`), SVG attributes in their XML form (`stroke-width`, `viewBox`, `xlink:href`), the DOM properties that Vue sets by their name (`tabIndex`, `innerHTML`, `textContent`), `data-*`, `aria-*`, listeners (`onClick`, `onClickOnce`, `onUpdate:modelValue`), and `class`, `style`, `key`, `ref`, `is`. Opt-in: the Vue binding still forwards every attribute by default.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/prop-filters.md#vue)
- **`@umber-style/is-prop-valid/react-native`** (the default export): the props of React Native's built-in components (`View`, `Text`, `Image`, `TextInput`, `ScrollView`, `Pressable`, the touchables, the lists, `Modal`, `Switch` and the rest), `aria-*`, `accessibility*`, handlers, `testID`, `nativeID`, `style`, `children`, `ref` and `key`. Opt-in: the React Native binding still forwards every prop by default.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/prop-filters.md#react-native)
- Each answer is kept by name after the first call, and the lists are expanded at the first call, not when the module is loaded.
- Each subpath exports the same function by name too, **`isPropValid`**: a CommonJS build that imports a subpath (the React binding's) reads it there.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/prop-filters.md)
- ESM and CommonJS builds with declarations; from `require`, the function is `.default` and `.isPropValid`. There is no root entry: the bare name of the package does not resolve.

### Packaging

- No dependencies and no peer dependencies. Each subpath carries its own list: `/react` and `/vue` share the names both spell the same way, and `/react-native` shares none.
- The lists follow `@types/react` 19.3, `vue` 3.5 and `react-native` 0.88.
- The first version is 0.2.0, the version of every package of this release, so that the family carries one number. MINOR: a new package.
