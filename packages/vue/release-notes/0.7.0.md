## @umber-style/vue@0.7.0

A release for the version that every package of the family carries and the new range of its dependencies; the style functions of an element share one argument, and the theme cannot be written in development.
([#66](https://github.com/soroush-tech/umber-style/issues/66), [#69](https://github.com/soroush-tech/umber-style/issues/69))

### Changed

- **Breaking, in development: the style functions of an element share one argument, frozen in development** (`@umber-style/core`). A styled component gives its functions one object in a render, `{ ...props, theme }`, made in the render and never kept, where each function got a copy of its own. With the development checks, a function that assigns or deletes a key of it throws:
  `[umber] A style function of "box-root" threw a TypeError of a write into a frozen object: Cannot define property tone, object is not extensible. In development the argument of a style function is frozen: it is one object, the props with the theme, shared by the style functions of the element in a render. Copy the argument before changing it: const own = { ...props }.`
  In production nothing is frozen, and a change to the argument is seen by the later functions of the same element. What to do: copy the argument before changing it, `const own = { ...props }`.
  ([#69](https://github.com/soroush-tech/umber-style/issues/69))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#object-styles-and-function-styles)
- **Breaking, in development: the theme a function gets cannot be written.** With the development checks, a write at any level into the theme given to a style function, a function sheet of `StyleSheet.create`, a function of `keyframes`, of `globalStyles` (for `Global`) or the function given to `ThemeProvider` as its `theme` throws, naming the path and the function:
  `[umber] theme.palette.text is set by a function of "ThemeProvider". The theme is one object, shared by every render and every request, so a change to it reaches all of them: never change it. Build a new object instead, such as { ...theme.palette, text: value }.`
  What to do: never write into the theme; build a new object instead. In production nothing changes.
  ([#69](https://github.com/soroush-tech/umber-style/issues/69))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/themes.md#the-theme-a-function-gets-is-shared-never-change-it)

### Packaging

- Depends on `@umber-style/core` `^0.7.0` (it was `^0.6.0`).
