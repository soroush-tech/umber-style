## @umber-style/vue@0.6.0

The theme below a provider is the same object for the same themes, and the binding exports `setNonceSource`, which Vue does not read, so that every binding has the same names.
([#64](https://github.com/soroush-tech/umber-style/issues/64), [#65](https://github.com/soroush-tech/umber-style/issues/65))

### Added

- **`setNonceSource`** (the core's), exported so that every binding has the name: Vue renders no server components, and nothing here reads it.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#server-components-a-nonce-for-each-request)

### Fixed

- A browser cache did not recognise a class whose label has an upper-case letter or a non-ASCII letter (`soroush-Typography-1p2bgvv`) in the style elements of a server: it read the name up to that letter, so after hydration the rule of every such class was written a second time. It reads the name whole now, so a server-rendered page keeps one rule for each class.
- A label with a character that a class name cannot hold (a space, `.`, `:`, `#`, `/`, a quote, `{`) broke the component: a space split the class attribute in two, and the rule's selector was wrong or invalid, so the component got no styles. In the class name a label now keeps `a-z`, `A-Z`, `0-9`, `_` and `-`; white space at its ends is trimmed and every other character becomes `-` (`card.title` is `card-title`, `Card Header` is `Card-Header`), with a development warning once for each such label. A label of those characters only gives the class name it always gave.

### Packaging

- Depends on `@umber-style/core` `^0.6.0` (it was `^0.5.0`).
