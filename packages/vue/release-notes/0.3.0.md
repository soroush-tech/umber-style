## @umber-style/vue@0.3.0

`useStyleValue` for a value that changes without a render, and the `nonce` option for a strict content security policy.
([#53](https://github.com/soroush-tech/umber-style/issues/53)) ([#13](https://github.com/soroush-tech/umber-style/issues/13))

### Added

- **`useStyleValue(initial, unit?)`**, of the default style and of `createStyle`, called in `setup`: a value that is a reference to a CSS variable in a style, with `value` in the shape of a ref; setting it changes the declaration of the variable in place, with no render. The type **`StyleValueRef`**.
  ([#53](https://github.com/soroush-tech/umber-style/issues/53))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#a-value-that-changes-without-a-render)
- The **`nonce`** option of `createStyle` and `configure`: the style element of the engine in the browser carries it. A server render gives the nonce of each request to `extractPageStyles`.
  ([#13](https://github.com/soroush-tech/umber-style/issues/13))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#content-security-policy)

### Changed

- The second theme class of a nested provider declares the themes of the nested providers above it and its own, merged, and no longer the theme of the outermost provider, which is on `:root` or on the class of `<html>` (`isRoot`) and reaches every element, portal content too. Before: a nested provider that changed one token declared every token the page used, with the values of the outermost theme, so a page that switched its theme by the class on `<html>` did not reach the tokens it had not changed. After: those tokens follow the class on `<html>`; directly under the outermost provider the two classes are one. `useTheme()` and the theme of a style function are the whole merged theme, as before.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/themes.md#the-provider)
- **Breaking for code that passed `hasRuleText`**: the option of `createStyle` and `configure` is named **`speedy`**, with the opposite meaning. Before: `hasRuleText: false` wrote the rules with `insertRule`. After: `speedy: true` does; the default is the same (`insertRule` in production, text otherwise). `hasRuleText` is in no type, and in development it gets one warning and is not read. Outside production each rule is the text of a style element of its own, so a test that reads the CSS joins the text of every `style[data-style="<prefix>"]` element.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/options.md#speedy)
- Through `@umber-style/core` 0.3.0, a theme switched while a page streams stays: a style element that arrives later with the root rule of the server no longer undoes the switch until the next declaration of the root theme.
  ([#48](https://github.com/soroush-tech/umber-style/issues/48))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md#limits)

### Packaging

- Depends on `@umber-style/core` `^0.3.0` (it was `^0.2.0`).
