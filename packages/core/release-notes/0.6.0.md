## @umber-style/core@0.6.0

A design system's page, rendered on a server, did again in every render work it had already done; this release finds that work again, gives server components a nonce for each request, and adds two development checks.
([#62](https://github.com/soroush-tech/umber-style/issues/62), [#63](https://github.com/soroush-tech/umber-style/issues/63), [#64](https://github.com/soroush-tech/umber-style/issues/64), [#65](https://github.com/soroush-tech/umber-style/issues/65))

### Added

- **`setNonceSource(source)`** and **`readNonceSource()`**: where the nonce of a request comes from, registered once, for the style elements of the server components build of the React binding, which calls the source once in each request. The bindings export `setNonceSource`.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#server-components-a-nonce-for-each-request)
- A development warning for a token in `variable` or `reference` mode whose value is a CSS-wide keyword (`inherit`, `initial`, `unset`, `revert`, `revert-layer`, in any letter case): a custom property takes it as itself, so the token does not do what it says. Once for each path, with what to write instead. `createTokens` takes the function it tells as a third argument.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/tokens.md#a-token-whose-value-is-a-css-wide-keyword)

### Changed

- A theme given as a new object with the contents of one seen before (a provider whose theme is made in each render) finds the root rule and the view made for that one, and `mergeTheme` gives the same theme for the same pair of objects, and for a given of the same contents, every time. The output is the same; the home page of the design system rendered in 0.071 ms instead of 0.317 ms on a server, with 140 KB allocated instead of 862 KB.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/performance.md)
- `getFullRules` gives the same list for a class while the cache holds it, and keeps the full rules of a theme class and of a root theme until the `@property` rules change, so a server render does not write them again for each element.
- The caches of one prefix that write into one page share its development check: each problem is told once, not once for each cache.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/testing.md#the-development-checker)

### Fixed

- A browser cache did not recognise a class whose label has an upper-case letter or a non-ASCII letter (`soroush-Typography-1p2bgvv`) in the style elements of a server: it read the name up to that letter, so after hydration the rule of every such class was written a second time. It reads the name whole now, so a server-rendered page keeps one rule for each class.
- A label with a character that a class name cannot hold (a space, `.`, `:`, `#`, `/`, a quote, `{`) broke the component: a space split the class attribute in two, and the rule's selector was wrong or invalid, so the component got no styles. In the class name a label now keeps `a-z`, `A-Z`, `0-9`, `_` and `-`; white space at its ends is trimmed and every other character becomes `-` (`card.title` is `card-title`, `Card Header` is `Card-Header`), with a development warning once for each such label. A label of those characters only gives the class name it always gave.

### Packaging

- No dependency of the family; `csstype` as before.
