## @umber-style/core@0.2.0

Two copies of the core in one program, as an app has them when one package is bundled into a server build next to another left external, now share the state that one copy registers and another reads, and a second copy says so in development.
([#52](https://github.com/soroush-tech/umber-style/issues/52))

### Added

- **`readSharedState(key, create)`**: the state that every copy of the packages loaded in the program shares, in one registry on `globalThis` under `Symbol.for('umber-style.registry')`. Each entry is keyed `<package>.<name>@<shape>`, so that a later release can change the shape of an entry without breaking an older copy. The bindings and `@umber-style/css` keep their shared state there.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/how-it-works.md#two-copies-in-one-program)
- In development, a copy of the core that is not the first in the program warns once: it names both versions when they differ, and, where there is a document, says that two copies of one version are loaded when they do not, with how that usually happens. A server of server components, which loads the core once for each of its two module graphs by design, is not warned about.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/how-it-works.md#two-copies-in-one-program)

### Fixed

- A name that `keyframes()` of one copy returned is known to the cache of another: `insertKeyframes()` no longer throws `is not a name that keyframes() returned`, and a class that uses the name writes its `@keyframes` rule.
- `findCache` finds the cache of a page that another copy made.
- Two caches of one prefix from two copies write a style element as two caches of one copy do: one that writes with `insertRule` keeps out of an element written by text, and neither takes the rules the other wrote for rules that a server sent.
- A wrapper made by one copy finds the labels of a component made by another, so its class names are the same with two copies (a server) as with one (the browser).

### Packaging

- No dependency on a sibling. MINOR: new public API (`readSharedState`).
