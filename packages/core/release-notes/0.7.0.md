## @umber-style/core@0.7.0

A release for the version that every package of the family carries, and a faster value repair: nothing it writes changes.
([#68](https://github.com/soroush-tech/umber-style/issues/68))

### Changed

- A cache with `hasValueRepair` remembers the text that each value was repaired to, and takes it again when it compiles that value again, which a render over a warm cache does for every class it names. The memo is the cache's, holds up to 10,000 values (then it is emptied), is emptied when the engine registers the values of a theme, so a changed token is repaired again, and is not used when a development check reports what repair leaves, so every report is still given. A reference that no suffix can follow is passed at once, and the text of a report is made only when there is a report to give it to. The text written is the same. In a warm `renderToString` of the design system's every-component page (82 components, `hasValueRepair` on) the page took 4.2 ms where it took 5.0 (the fastest of 7 rounds, with the two changes of `@umber-style/react` below) and allocated 5.1 MB where it allocated 6.4 MB; the home page took 73 us where it took 86.

### Packaging

- No dependency of the family; `csstype` as before.
