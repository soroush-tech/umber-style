## @umber-style/core@0.1.0

First release. The UmberStyle engine: theme tokens become CSS variables, a style becomes one class that serves every theme, and a theme is a class on an element. It knows no framework and has no browser global at module level, so it runs on the server and in plain JavaScript.
([#9](https://github.com/soroush-tech/umber-style/issues/9))

### Added

- **`createEngine`**, the cache and sheets it writes to, the style serializer, `extractPageStyles` for server rendering, and the token helpers `at`, `alpha` and the calc functions.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/plain-javascript.md)
- **`keyframes`** and **`globalStyles`**, and the engine's `keyframes`, `insertKeyframes`, `insertGlobal` and `resolveGlobal`: an animation is registered by name and its `@keyframes` rule is written once, when a class or a global rule uses it; global rules go into the `global` layer, are counted, and are removed when released. A function of the theme given to either one that lists the keys of the theme throws a `TypeError`.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- The root theme: `engine.declareRoot` declares a theme on `:where(:root)`, in one rule that a change rewrites, and `extractPageStyles` sends it. A theme can be a function of the theme above it (`resolveThemeInput`, `mergeTheme`).
  ([#46](https://github.com/soroush-tech/umber-style/issues/46))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/root-theme.md)
- The option **`hasValueRepair`**: the string forms of token maths that are not valid CSS (two hex digits of alpha after a token, a minus before one, `ms` or `s` after one) are rewritten as `alpha`, `negate` and `calc` write them. Off by default.
  ([#37](https://github.com/soroush-tech/umber-style/issues/37))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/tokens.md)
- In development, the browser is asked with `CSS.supports` about each declaration the cache inserts, and one it does not support is warned about once.
  ([#39](https://github.com/soroush-tech/umber-style/issues/39))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/testing.md)
- **`parseStyleTemplate`** and **`parseKeyframesTemplate`**: CSS text of a template string into a style object or keyframes steps. `@umber-style/css` uses them; `styled`, `css` and `keyframes` of the bindings do not take templates yet.
  ([#47](https://github.com/soroush-tech/umber-style/issues/47))
- For server-rendering set-ups: the cache option `onInsert` (a name and the CSS text of each group of rules written), `extractPageStyleParts` (the CSS of a page in a global part and a part for its classes), and `createStyleSelector`. A browser cache also reads the `<style data-umber>` elements of its prefix.
  ([#48](https://github.com/soroush-tech/umber-style/issues/48))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md)
- ESM and CommonJS builds with declarations.

### Packaging

- Depends on `csstype` for the types of CSS properties.
- `@umber-style/react`, `@umber-style/react-native`, `@umber-style/vue`, `@umber-style/css`, `@umber-style/cache`, `@umber-style/server` and `umber-style` depend on this package and share its one engine.
