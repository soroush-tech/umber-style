## @umber-style/core@0.1.0

First release. The UmberStyle engine: theme tokens become CSS variables, a style becomes one class that serves every theme, and a theme is a class on an element. It knows no framework and has no browser global at module level, so it runs on the server and in plain JavaScript.
([#9](https://github.com/soroush-tech/umber-style/issues/9))

### Added

- **`createEngine`**, the cache and sheets it writes to, the style serializer, `extractPageStyles` for server rendering, and the token helpers `at`, `alpha` and the calc functions.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/plain-javascript.md)
- **`keyframes`** and **`globalStyles`**, and the engine's `keyframes`, `insertKeyframes`, `insertGlobal` and `resolveGlobal`: an animation is registered by name and its `@keyframes` rule is written once, when a class or a global rule uses it; global rules go into the `global` layer, are counted, and are removed when released. A function of the theme given to either one that lists the keys of the theme throws a `TypeError`.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- The root theme: `engine.declareRoot` declares a theme on `:where(:root)`, in one rule that a change rewrites, and `extractPageStyles` sends it. A theme can be a function of the theme above it (`resolveThemeInput`, `mergeTheme`).
  ([#46](https://github.com/soroush-tech/umber-style/issues/46))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/root-theme.md)
- The option **`hasValueRepair`**: the string forms of token maths that are not valid CSS (two hex digits of alpha after a token, a minus before one, `ms` or `s` after one) are rewritten as `alpha`, `negate` and `calc` write them. Off by default.
  ([#37](https://github.com/soroush-tech/umber-style/issues/37))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/tokens.md)
- In development, the browser is asked with `CSS.supports` about each declaration the cache inserts, and one it does not support is warned about once.
  ([#39](https://github.com/soroush-tech/umber-style/issues/39))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/testing.md)
- **`parseStyleTemplate`** and **`parseKeyframesTemplate`**: CSS text of a template string into a style object or keyframes steps. `@umber-style/css` uses them; `styled`, `css` and `keyframes` of the bindings do not take templates yet.
  ([#47](https://github.com/soroush-tech/umber-style/issues/47))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/css.md#as-a-tag)
- For server-rendering set-ups: the cache option `onInsert` (a name and the CSS text of each group of rules written), `extractPageStyleParts` (the CSS of a page in a global part and a part for its classes), and `createStyleSelector`. A browser cache also reads the `<style data-umber>` elements of its prefix.
  ([#48](https://github.com/soroush-tech/umber-style/issues/48))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md)
- **`engine.readThemeText`**, **`createThemeRule`** and **`ROOT_SELECTOR`**: the variables of a theme as text, and the rule of a theme class or of the root theme, for a rule that a binding builds elsewhere (the browser part of a provider of the React server build). `readThemeText` works with no base theme and gives none to the engine. **`createThemeId`** names the theme class of that text without registering it, and **`engine.tokenOptions`** gives the token options that name the variables. **`isDevelopment`** tells a binding whether to warn. `findMissingStyles` leaves out `<prefix>-theme-0`, the class of a theme that declares nothing, which has no rule.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#server-components)
- ESM and CommonJS builds with declarations.
- **`createCssEntry`** and **`createDeferredObject`**: what `css()` of the bindings is made of, a sheet entry of merged styles that a default style can make before `configure()`. A sheet entry under a selector of global styles gives its style.
  ([#36](https://github.com/soroush-tech/umber-style/issues/36))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)
- The template form: `keyframes` and `globalStyles` can be used as a tag, and `readStyleArguments` and `createComponentSelector` give the bindings the template form of `styled` and a styled component as a selector.
  ([#47](https://github.com/soroush-tech/umber-style/issues/47))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md)
- The types apps import: `CSSObject`, `Keyframes`, `SerializedStyles`, `Interpolation`, `UmberCache` (moved here from `@umber-style/cache`) and the types of a template's values.
  ([#49](https://github.com/soroush-tech/umber-style/issues/49))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md)
- `engine.withCache(cache)`: the engine of the same theme over another cache, with the cache's prefix, made once for each cache; the engines share one base theme. A sheet entry given to another cache is written there (`cache.adoptEntry`, `engine.adoptSheet`, `findEntryCache`). What a cache provider of a binding uses.
  ([#38](https://github.com/soroush-tech/umber-style/issues/38))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/plain-javascript.md)
- **`createDomSheet(key, container)`** uses the document of its container, and a cache over it reads that document (an iframe's): the page scan, the watch of new style elements, the stamp check and the development check. The cache also notices style elements added as children of `<body>`, where a registry streams them.
  ([#38](https://github.com/soroush-tech/umber-style/issues/38))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md#another-document)
- The global rules of a page are those of the page: `extractPageStyles` (and `extractPageStyleParts`, `extractPage` with `rendered`) holds a set that a `Global` rendered only for the page whose markup carries it or names it in a marker (`<meta name="<prefix>-global">`, `<!--<prefix>-global ...-->`; `createGlobalMarker` makes one), so a server that rendered one page no longer sends its global rules with every other page. `cache.insertGlobal(set, { isRendered: true })` is what the bindings call; `engine.insertGlobal` stays app-wide, in every page.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- **`findCache(prefix, document)`**: the first cache of a prefix that writes into a style element of a document, for code with no engine of its own. A cache reads the style elements that arrived since the watch of the head last reported, before it takes global rules over from the page, and reads a style element that React streams into the body (`media="not all"`) once it is moved to the head.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- The `label` option of a styler, the label of its classes as it is written. A style function may return a list, nested to any depth (`StyleResult`, `InterpolationResult`), and a cache takes lists in `css`, `cssWith` and `cssHeld`; in development, what a style function returns that is not a style is warned about once for each message. A key whose value is `undefined`, `null` or `false` declares nothing and no longer erases the same key of an earlier style. `withTagShorthands` makes each tag an own enumerable member. `mergeDeep` returns the base for an override that is the base itself, so a branch both sides share keeps its identity.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md)
- Labels are joined, never replaced: `mergeStyles`, `css` and `cssWith` write the labels of what they merge in order, joined by `-`, each once (`<prefix>-Typography-Link-<hash>`), and the `label` option of `cssWith` and `cssHeld` comes first. A styler that wraps another gives every class it makes the labels of the whole chain, inner first, so the base class and the props class of `styled(Paper, { label: 'Popover' })` are `<prefix>-Paper-Popover-<hash>`, and an engine class given in `className` adds its labels after those of the element (`<prefix>-Typography-Link-<hash>`); a wrapper without a label shares the base of the wrapped one, as before. Where the base is the whole class of a wrapped styler with no function, that class stays in front of it, so the wrapped component as a selector still matches.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#wrapping-a-styled-component)
- **`hasRuleText`** (`createDomSheet(key, container, { hasRuleText })`, `createCache`, `createEngine`): a DOM sheet writes each rule as a text node of its style element, so `textContent` and the element inspector show the live rules, removing a node with its rule; or with `insertRule`. Text is the default outside production, `insertRule` in production. A text sheet writes in an element of its own next to one that a server filled, and the cache never reads its own text as a server's.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/how-it-works.md)
- One text format for every rule the engine gives: `name:value;` for each declaration, the last one too, no space or newline around the structure, a selector list joined by `,` with no space (`html,body`, the selectors of global styles too). It is stated in the docs.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/how-it-works.md#the-text-of-a-rule)
- A `css()` value (`SerializedStyles`) has `name`, the class it is used under on its own, and `styles`, the text of its style, both read without writing its rule.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)
- **`Engine.givenTheme`** and **`Engine.adoptTheme`**: the base theme given on purpose (`createEngine(theme)`, `setTheme`), apart from the shape that the first provider or `themeClass` gives the engine. What reads the theme with no provider reads the given one only, so the theme of a provider does not outlive it.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/themes.md#the-base-theme)
- The development checks: `hasDevChecks: true` turns them on in a test run, and with no `document`; a value that no CSS property takes (`true`, a function, `NaN`, an object in a list of values) is warned about; the engine's check of what a style function returns follows `hasDevChecks`; a class with a label is named with it in the message of `CSS.supports`. `Cache.hasDevChecks` says whether they are on.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/testing.md#the-development-checker)
- The web style types have a default that takes the code of an app as it is: a property takes its known values, which editors still complete, and any string or number; any other key holds a nested style or a value, so a key computed at run time and an object whose values were widened to `string` compile. **`StyleTypeOptions`**, an interface an app merges `isStrict: true` into, switches on the strict types, which check keys and keywords as before. `WebStyleObject`, `WebProperties` and every type made of them follow it, and the declarations keep their names, so the switch works on the published packages.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#the-default-types-and-the-strict-switch)

### Packaging

- Depends on `csstype` for the types of CSS properties.
- `@umber-style/react`, `@umber-style/react-native`, `@umber-style/vue`, `@umber-style/css`, `@umber-style/cache`, `@umber-style/server` and `umber-style` depend on this package and share its one engine.
