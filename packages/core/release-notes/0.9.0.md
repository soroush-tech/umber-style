## @umber-style/core@0.9.0

A page of Next.js loads no more scripts than on 0.7.0, as the code the two entries share keeps its own export names; `css()` given a function says what to use instead; the core makes the handles of a sheet made from a function of the theme; after a client-side navigation the browser applies a rule that a server component and a client component share once.
([#84](https://github.com/soroush-tech/umber-style/issues/84), [#87](https://github.com/soroush-tech/umber-style/issues/87), [#88](https://github.com/soroush-tech/umber-style/issues/88), [#89](https://github.com/soroush-tech/umber-style/issues/89), [#91](https://github.com/soroush-tech/umber-style/issues/91))

### Added

- **`ThemedEntry`** and **`ThemedEntries`** (types) - the handle of a name of a sheet made from a function of the theme, and the handles of such a sheet by name. The bindings make them with `createThemedSheet` of `@umber-style/core/internal`, which also has `readThemedSource` and `rejectThemedEntries`.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)

### Changed

- **`css()` given a function says what to use instead.** A function given to `css()`, as an argument (alone or in a list) or as an interpolation of its template, threw a `TypeError` that said only that `css()` has no props. It now throws one message on every path and in every binding, which names `css` and the two things that take a function:
  `css(): a function is not a style here, as an argument or as an interpolation: css() makes a class with no component, so it has no props or theme to call it with. For a value of the props, use a styled component's style function; for a value of the theme, give an entry of StyleSheet.create((theme) => ...) to the style prop.`
  The message is made in the core (`rejectFunctions` and `readStaticTemplate` of `@umber-style/core/internal`), so the bindings and `@umber-style/css` give the same one. `css()` with no function in it is unchanged.
  ([#87](https://github.com/soroush-tech/umber-style/issues/87))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)
- **A style passed from a server component to a client component says, in development, that its CSS cannot cross.** `flattenStyle` of `@umber-style/core/internal` takes the cache of a styled component as a third argument: it resolves a handle there, and, in a binding that does not merge style objects (React), warns once for each key about an object of one `--umber-entry-` or `--umber-themed-` key with no brand, what an entry or a handle becomes when React passes it to a client component: `[<prefix>] A style was passed from a server component to a client component (<key>), and its CSS cannot cross: import the sheet in the client component, and pass a plain value such as a string to choose the style.` Entries are unchanged.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-style-passed-from-a-server-component)
- **A handle where no theme is known is a `TypeError`:** among the values of a class (`apply`, `css()`), the styles of `styled` (when the component is made), `globalStyles` and `Global`. The message names the place and the fix, for example `apply(): an entry of a sheet made from a function of the theme (StyleSheet.create((theme) => ...)) has no theme here. Give it to the style prop of a styled component, which resolves it with its theme, or read the entry from useStyle(sheet) first.`
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **The development warning of a class that no rule names says what to do when it is a class name passed as text:** `... which no rule names: if it is the class of a sheet entry passed as text (String(entry), entry.className), use the entry itself where the style is used, importing its sheet there: a class name carries no rule`.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-style-passed-from-a-server-component)

### Fixed

- **A rule the browser's cache wrote is not applied twice after a client-side navigation.** When a client component writes a class in its render and the server's payload brings the same class in the commit (the element React hoists for a `<style href precedence>`, or the head element of `NonceStyles` under a nonce), the cache deletes, from the sheet of that element, each rule whose text is one it wrote itself, for a class it does not hold, when the element comes before its own elements. The copy that applied stays, the other rules and the text of the element stay, and an element left with no rule stays in the document. `scanStyleText` lists the top-level rules that name a class (`classRules`).
  ([#91](https://github.com/soroush-tech/umber-style/issues/91))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/nextjs.md#limits)

### Packaging

- **The code the two entries share keeps its own export names.** The main entry and `@umber-style/core/internal` share one file of code, which the build exported under minified names (`export { D as globalStyles }`) and the entries re-exported renamed. Turbopack adds a module for each renamed name a binding imports, and those modules pushed the chunk of the React binding past the size at which Next.js merges chunks, so a page of a Next.js app could load one more script in its first HTML than on 0.7.0. The build now keeps the names (`minifyInternalExports: false`). On a design system's Next.js 16.4.6 App Router app, its two pages load 10 and 9 scripts again (11 and 10 on 0.8.0, 10 and 9 on 0.7.0), 791,426 and 692,578 bytes of script (251,998 and 220,496 gzipped) where 0.8.0 loaded 792,149 and 693,281 (252,748 and 221,238), and the HTML (its script tags aside), the CSS and the server component payload of each page are the same as with 0.8.0. The code is the same; only the names of the shared file's exports change. `pnpm smoke:packed` fails when a shared file of a package is built with minified export names again.
  ([#84](https://github.com/soroush-tech/umber-style/issues/84))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/releasing.md#the-packed-tarball-test)
