## @umber-style/core@0.9.0

A page of Next.js loads no more scripts than on 0.7.0, as the code the two entries share keeps its own export names; and `css()` given a function says what to use instead.
([#84](https://github.com/soroush-tech/umber-style/issues/84), [#87](https://github.com/soroush-tech/umber-style/issues/87))

### Changed

- **`css()` given a function says what to use instead.** A function given to `css()`, as an argument (alone or in a list) or as an interpolation of its template, threw a `TypeError` that said only that `css()` has no props. It now throws one message on every path and in every binding, which names `css` and the two things that take a function:
  `css(): a function is not a style here, as an argument or as an interpolation: css() makes a class with no component, so it has no props or theme to call it with. For a value of the props, use a styled component's style function; for a value of the theme, give an entry of StyleSheet.create((theme) => ...) to the style prop.`
  The message is made in the core (`rejectFunctions` and `readStaticTemplate` of `@umber-style/core/internal`), so the bindings and `@umber-style/css` give the same one. `css()` with no function in it is unchanged.
  ([#87](https://github.com/soroush-tech/umber-style/issues/87))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)

### Packaging

- **The code the two entries share keeps its own export names.** The main entry and `@umber-style/core/internal` share one file of code, which the build exported under minified names (`export { D as globalStyles }`) and the entries re-exported renamed. Turbopack adds a module for each renamed name a binding imports, and those modules pushed the chunk of the React binding past the size at which Next.js merges chunks, so a page of a Next.js app could load one more script in its first HTML than on 0.7.0. The build now keeps the names (`minifyInternalExports: false`). On a design system's Next.js 16.4.6 App Router app, its two pages load 10 and 9 scripts again (11 and 10 on 0.8.0, 10 and 9 on 0.7.0), 791,426 and 692,578 bytes of script (251,998 and 220,496 gzipped) where 0.8.0 loaded 792,149 and 693,281 (252,748 and 221,238), and the HTML (its script tags aside), the CSS and the server component payload of each page are the same as with 0.8.0. The code is the same; only the names of the shared file's exports change. `pnpm smoke:packed` fails when a shared file of a package is built with minified export names again.
  ([#84](https://github.com/soroush-tech/umber-style/issues/84))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/releasing.md#the-packed-tarball-test)
