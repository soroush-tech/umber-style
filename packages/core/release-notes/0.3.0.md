## @umber-style/core@0.3.0

Style elements for strict content security policies, values that a style reads without a render, and a theme switched while a page streams that stays.
([#13](https://github.com/soroush-tech/umber-style/issues/13)) ([#53](https://github.com/soroush-tech/umber-style/issues/53)) ([#48](https://github.com/soroush-tech/umber-style/issues/48))

### Added

- **`nonce`**, an option of `createCache`, `createEngine` and `createDomSheet`: the style element that the cache makes in the browser carries it, in both ways of writing, and it is `cache.nonce` for the tags made from the cache. It is in no rule, class name or stamp.
  ([#13](https://github.com/soroush-tech/umber-style/issues/13))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#content-security-policy)
- **`createStyleTag(cache, { nonce })`** and the **`nonce`** option of **`extractPageStyles`**: the tag carries the nonce of the call, else that of the cache, escaped. **`createNonceAttribute`** writes that attribute for other tags.
  ([#13](https://github.com/soroush-tech/umber-style/issues/13))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#content-security-policy)
- **`createLiveValue`**, **`declareLiveValue`**, **`isLiveValue`**, **`writeLiveValue`** and the types **`LiveValue`** and **`LiveRule`**: the values that `useStyleValue` of the web bindings gives, a reference to a CSS variable whose rule is changed in place. `add`, `subtract`, `multiply`, `divide` and `negate` take a value as an operand.
  ([#53](https://github.com/soroush-tech/umber-style/issues/53))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#a-value-that-changes-without-a-render)
- **`cache.document`**: the document a cache serves, none on a server.

### Changed

- **Breaking for code that passed `hasRuleText`**: the option is named **`speedy`**, with the opposite meaning, in `createCache`, `createEngine` and `createDomSheet`. Before: `hasRuleText: true` wrote each rule as text, `hasRuleText: false` with `insertRule`. After: `speedy: false` writes each rule as text, `speedy: true` with `insertRule`; the default is the same (`insertRule` in production, text otherwise). `hasRuleText` is in no type any more, and in development an options object that still has it gets one warning with what to write instead; its value is not read.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/options.md#speedy)
- Outside production (rules written as text), every rule is the text of a `<style data-style="<prefix>">` element of its own, placed right after the element of the rule before it, instead of a text node of one element. The browser parsed the whole text of that element again for every rule, so writing N rules grew with the square of N: in jsdom 800 classes took 49 seconds, now 306 milliseconds; in Chromium 1600 rules take a few times as long as with `insertRule`. A test that reads the CSS from the page joins the text of every element of the prefix. Production, which writes with `insertRule` into one element, is unchanged.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/options.md#cache-options)

### Fixed

- A theme switched while a page streams stays. A style element that streams in after the browser's cache declared its root theme brought the `:where(:root)` rule that the server wrote; it came later in the document than the rule of the cache and won with the server's theme, so the page went back to it until the next declaration of the root theme. The cache now removes such a rule as the element arrives; its other rules are kept.
  ([#48](https://github.com/soroush-tech/umber-style/issues/48))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md#limits)
- `findAnimationNames` returns for a rule whose `animation` value has no closing `;` (text the engine did not write): it searched the rule from its start again and never returned. The engine's own rules are read as before.
- `isSameView` returns for a theme view that refers to itself, and a view with no cycle gives the answer it gave before.

### Packaging

- No dependency on a sibling. Released as 0.3.0 with every package of the family, which carry one version.
