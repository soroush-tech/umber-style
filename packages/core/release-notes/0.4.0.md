## @umber-style/core@0.4.0

Hover, press, focus and disabled styles written once for the web and React Native, as state keys.
([#42](https://github.com/soroush-tech/umber-style/issues/42))

### Added

- **`state(name)`**, with the types **`StateName`** and **`StateKey`**: the key of a style for one of four states, `hovered`, `pressed`, `focused` and `disabled`, used with `at`: `...at(state('pressed'), { opacity: 0.7 })`. Any other name is a type error, and in development a warning. The serializer writes each key as the selector an author writes for it today (`&:hover`, `&:active`, `&:focus-visible`, `&:disabled, &[aria-disabled="true"]`): the same rules, the same class name and the same order as that selector key. It nests and combines with `when()`, `whenScheme()`, media keys and selectors as a selector does.
  ([#42](https://github.com/soroush-tech/umber-style/issues/42))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#interaction-states)
- **`readState(key)`** and **`STATE_SELECTORS`**: the state a key names, and the selector each state is written as, for the bindings.
  ([#42](https://github.com/soroush-tech/umber-style/issues/42))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#interaction-states)
- **`hasStyleMemo`**, an option of `createCache` and of the engine, off by default: the cache remembers the class of a style by its contents, so that the same contents in a new object (a style function's result on each render, `({ isMobile }) => ({ fontSize: isMobile ? 12 : 48 })`) are found without being compiled and hashed again. The class names, the rules and their order are the same with it on and off. It covers style objects alone whose values are strings and numbers, nested at any depth; a class name, a sheet entry, a list, `alpha()`, a live value or a getter in a nested style takes the full path, and with the development checks or value repair there is no memo. A style is remembered the second time its class is made, and the memo holds at most 10,000 steps for each set of style options. Measured with it on against off (local files, one CPU, the median of five rounds): two values in turn 620 ns to 160 ns, the small style one of four 1.17 us to 0.41 us, the large one 9.57 us to 4.87 us, a nested style 1.46 us to 0.54 us, the same object again 1.08 us to 0.33 us, and a style that never repeats level (1.87 us and 1.88 us); rendered to a string, warm, with style elements (nine rounds): 48 elements choosing between two styles 145.7 us to 113.5 us, 48 of 48 combinations 255.2 us to 205.1 us, the tree of 500 2.94 ms to 2.35 ms. It holds up to about 4 MB at its cap, and adds 0.8 KB gzipped to the core. With it off the path is the one before it, level with it in every case measured.
  ([#10](https://github.com/soroush-tech/umber-style/issues/10))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/options.md#hasstylememo)

### Changed

- A cache over a document, and `createDomSheet`, add nothing to the document when they are made: the `<style data-style="<key>">` element is found or made when the first rule is written, with the key and the nonce of the sheet, at the end of its container, in both ways of writing (`speedy`). Before, it was made, empty, when the cache was made, so a style made at the top of a module with no nonce left an element with no nonce for a cache of the same key that has one (a registry's) to write into, which a strict content security policy refuses. An empty element of the key that the page placed is still used; the first sheet of the key to write takes it. Written with `insertRule`, the element stays when its last rule is removed. ([#13](https://github.com/soroush-tech/umber-style/issues/13))
- Faster, with the same rules, class names, order and warnings
  ([#10](https://github.com/soroush-tech/umber-style/issues/10)). In the benchmark gate, against 0.3.0
  built from its tag, in its sandbox (one CPU, the median of five rounds): the same style again 1.33 us
  to 0.92 us; five classes merged 7.22 us to 0.30 us; a new small style 3.89 us to 3.12 us and a new
  large one 32.1 us to 21.4 us; the CSS of a page 154 us to 123 us; a new theme class 416 us to 255 us;
  a theme and its variables 1.16 ms to 0.58 ms. What changed:
  - a class that is written already is not compiled for its selector again (with the development
    checks it still is, for the check);
  - a merge of class names alone (`css(a, b)`, `cx`) is remembered, at most 1000 for each set of style
    options, and used while each name still has the same style;
  - the serializer reads the keys of a style without making pairs, and joins a nested selector without
    lists when there is no comma;
  - the tokens of a theme skip the lookups of `modes` and `registered` when there are none, and the
    engine of a fresh cache (a `CacheProvider`'s) takes the tokens the family made for the same theme
    object and prefix;
  - the scan of a page's HTML compares names in place and reads a repeated class value once;
  - the classes of a page are sorted by keys made once.
- The warning for `hasRuleText`, the warning for two copies of the core and the warning of `state()` for
  an unknown name are left out of a bundle that writes `production` for `process.env.NODE_ENV`; they
  fire in development as before.

### Packaging

- No dependency on a sibling. Released as 0.4.0 with every package of the family, which carry one version.
