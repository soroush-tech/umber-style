## @umber-style/core@0.8.0

Released for the version that every package of the family carries, with the style memo working with value repair.
([#75](https://github.com/soroush-tech/umber-style/issues/75), [#76](https://github.com/soroush-tech/umber-style/issues/76), [#82](https://github.com/soroush-tech/umber-style/issues/82))

### Changed

- **`hasStyleMemo` works with `hasValueRepair`.** A set of style options with value repair had no style memo, because a repaired value reads the declared values of the tokens. It now has one, and each time the engine gives the cache new declared values (a new base theme) the memo of every set of style options with value repair is emptied, so it never names a class made with the values of before. The option stays off by default, and the classes and rules are the same with it on and off. In a warm `renderToString` of a design system's every-component page (82 components, value repair on, `hasStyleMemo: true`), the tarballs packed before and after the change, each page in its own Node 26.4 process, `NODE_ENV=production`, 7 rounds of 300 timed renders after 100, the order alternated: the fastest render took 3.41 ms where it took 3.97, the median 3.95 ms where it took 4.35, and a render allocated 3.6 MB where it allocated 4.7 (the median growth of the heap over 30 batches of 5 renders, after a collection); with the option off the fastest render took 3.98 ms where it took 3.93, within the noise of the run. The home page took 41 us where it took 44 (fastest), 53 us where it took 63 (median), and allocated 90 KB where it allocated 108. The HTML and the CSS of both pages are byte for byte the same with the memo on and off, before and after.
  ([#76](https://github.com/soroush-tech/umber-style/issues/76))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-memo.md#with-value-repair)

### Fixed

- **A merge of class names is made again after the declared values change.** With `hasValueRepair`, the cache remembers the class it makes for a list of class names, and that class was made with the declared values of then: after `registerValues` gave a token a new value, `css(a, b)` still returned the class with the old repair. `registerValues` now empties the memo of merges of every set of style options with value repair, as it empties the memo of contents, so the class is the one a cache with no memo makes. Without value repair the memo keeps its classes, as before.
  ([#82](https://github.com/soroush-tech/umber-style/issues/82))
