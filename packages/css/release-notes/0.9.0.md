## @umber-style/css@0.9.0

Released for the version that every package of the family carries; `css` given a function throws the error of every binding's `css()`, which says what to use instead.
([#85](https://github.com/soroush-tech/umber-style/issues/85), [#87](https://github.com/soroush-tech/umber-style/issues/87))

### Changed

- **`css` given a function throws, and says what to use instead.** A function as an interpolation of a template threw a `TypeError` of this package's own, and a function given as an argument (alone or in a list) was dropped with no error, so `css(fn)` gave `''`. Both now throw the error of every binding's `css()`:
  `css(): a function is not a style here, as an argument or as an interpolation: css() makes a class with no component, so it has no props or theme to call it with. For a value of the props, use a styled component's style function; for a value of the theme, give an entry of StyleSheet.create((theme) => ...) to the style prop.`
  What to do: a value of the props or of the theme belongs to a styled component of a binding; here, call the function yourself and give `css` what it returns. `css` with no function in it is unchanged.
  ([#87](https://github.com/soroush-tech/umber-style/issues/87))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/css.md#css)
