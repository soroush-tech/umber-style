## @umber-style/react@0.9.0

Released for the version that every package of the family carries; `css()` given a function says what to use instead; `style={sheet.card}` takes a handle of a sheet made from a function of the theme, and `SheetStyleProp` types a style prop of entries only; a styled component rendered from a server component and a client component has its rule once in the page after a client-side navigation; `withTheme` and `withStyle` give a class component the theme and the entries of a sheet.
([#85](https://github.com/soroush-tech/umber-style/issues/85), [#87](https://github.com/soroush-tech/umber-style/issues/87), [#88](https://github.com/soroush-tech/umber-style/issues/88), [#89](https://github.com/soroush-tech/umber-style/issues/89), [#91](https://github.com/soroush-tech/umber-style/issues/91), [#93](https://github.com/soroush-tech/umber-style/issues/93))

### Added

- **`style={sheet.card}`: a handle of a sheet made from a function of the theme.** Each name of `StyleSheet.create((theme) => ...)` is a handle, a frozen object that holds the sheet and the name and computes nothing. The `style` of a styled component (the client build, its server render, and the server components build) resolves it with the theme it renders under, alone, in lists and with falsy values, through the binding's own `useStyle`, so the class and the rules are exactly those of `style={useStyle(sheet).card}` under the same provider. `useStyle` and object sheets are unchanged.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **`SheetStyleProp`** - the type of a `style` prop that takes sheet entries only: an entry (of `StyleSheet.create`, `useStyle` or `css()`), a handle, `false`, `null`, `undefined` and nested lists of them. A plain style object and a string are type errors. It is a part of `StyleProp`, so a component passes it on to its parts as it is.
  ([#89](https://github.com/soroush-tech/umber-style/issues/89))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#sheet-entries-only)
- **`withTheme`** and **`withStyle`** - the class-component twins of `useTheme` and `useStyle`, in the client build, its server render and the server components build, from the direct imports and from `createStyle()`. `withTheme(Card)` renders `Card` with `theme` set to `useTheme()`, and `withStyle(sheet)(Card)` with `styles` set to `useStyle(sheet)` (an object sheet or a sheet made from a function of the theme, made once at module level), called in the wrapper's render: the same values, the same entry objects, under the same provider. The wrapper takes the props of the component without `theme` (or `styles`), forwards `ref` (a prop in React 19: the instance of a class component), keeps the statics that are not React's own, and is named `withTheme(Card)` or `withStyle(Card)`. `theme` is typed as `useTheme()` returns it and `styles` as `useStyle(sheet)` does: a component whose `theme` is of another type, or whose `styles` names an entry the sheet does not have, is a type error. The types `WrappedComponent`, `StyleWrapper` and `PropsTaking` name them.
  ([#93](https://github.com/soroush-tech/umber-style/issues/93))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react.md#class-components-withtheme-and-withstyle)

### Changed

- **`css()` given a function says what to use instead.** A function given to `css()`, as an argument (alone or in a list) or as an interpolation of its template, threw a `TypeError` that said only that `css()` has no props. It now throws one message on every path and in every binding, which names `css` and the two things that take a function:
  `css(): a function is not a style here, as an argument or as an interpolation: css() makes a class with no component, so it has no props or theme to call it with. For a value of the props, use a styled component's style function; for a value of the theme, give an entry of StyleSheet.create((theme) => ...) to the style prop.`
  With `css` of the default style (`import { css } from '@umber-style/react'`) the error comes at the first use of the value, where the entry is made, as before; with `css` of `createStyle()` and in the server build it comes at the call. `css()` with no function in it is unchanged.
  ([#87](https://github.com/soroush-tech/umber-style/issues/87))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#css)
- **`sheet.card` of a sheet made from a function of the theme is a handle.** It was `undefined`, and a type error; it is now typed `ThemedEntry`, and a misspelt name is still a type error. The type tests that asserted the error were changed to assert the handle. Names that frameworks and serializers read on any object are not handles: the sheet's own members, the members of every object, `then`, `toJSON`, `$$typeof` and names that start with `__`.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **A handle where no theme is known is a `TypeError`, in every build:** `apply`, `css()`, the styles of `styled`, `globalStyles`, `Global`, a plain element of the client build (it reads the keys of its `style`), and the text of a handle (`className={sheet.card}`). In the server components build a plain element given a handle in `style` writes nothing instead, with no error: the key of a handle holds `null` there, because React reads every key of a prop for a message of development. The message names the place and the fix, for example `apply(): an entry of a sheet made from a function of the theme (StyleSheet.create((theme) => ...)) has no theme here. Give it to the style prop of a styled component, which resolves it with its theme, or read the entry from useStyle(sheet) first.`
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md#a-sheet-of-the-theme-without-a-hook)
- **`StyleProp` takes a handle (`ThemedEntry`)**, and `useStyle` has an overload for a sheet of handles. `useThemeView` reads its context with `use`, so that a styled component with no function style can read the theme only in the renders where it is given a handle.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
- **A style passed from a server component to a client component is not supported, and says so in development.** An entry, an entry of an object sheet, a handle, a `css()` value or a class name given to a client component as a prop arrives without its CSS and is unstyled, as in 0.8.0. A styled client component given an entry or a handle that crossed now warns once for each key (a class name gets the fix of the warning of a class that no rule names), in its server render and in the browser: import the sheet in the client component, and pass a plain value such as a string to choose the style. The slot pattern works within one side.
  ([#88](https://github.com/soroush-tech/umber-style/issues/88))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/nextjs.md#styles-stay-on-their-side)

### Fixed

- **A styled component rendered from a server component and from a client component on one page under `StyleRegistry` has its rule once after a client-side navigation**, with a nonce and without one: the engine's cache in the browser deletes the copy the server's payload brings of a class it wrote for the client component (`@umber-style/core` 0.9.0). In the first HTML the rule is once with a nonce, where both builds hand it to the registry; with no nonce it stays twice, in the element React hoists and in the registry's (one extra copy of the same rule for each such style, bytes only), as the Limits of the Next.js page say.
  ([#91](https://github.com/soroush-tech/umber-style/issues/91))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/nextjs.md#limits)
