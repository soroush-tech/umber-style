## @umber-style/react@0.8.0

Released for the version that every package of the family carries; a theme with hidden helpers crosses from a server provider as plain data, and client components below it keep the helpers of the base theme where the sizes are the same; and the Next.js registry takes every Next.js 16 release that CI runs it on, from 16.3.
([#75](https://github.com/soroush-tech/umber-style/issues/75), [#81](https://github.com/soroush-tech/umber-style/issues/81), [#78](https://github.com/soroush-tech/umber-style/issues/78))

### Fixed

- A theme whose objects have hidden members (not enumerable, or under a symbol: the `up`, `down` and `between` helpers that a design system puts on `breakpoints` with `Object.defineProperty`) no longer makes the development server print "Only plain objects can be passed to Client Components from Server Components" for each request: a provider of a server component sends a copy of each such object with its enumerable members, with no warning for them (a function under an enumerable key is still reported). In the browser, a client component below it reads the hidden helpers of the theme below the provider (the base theme of the client build, or a provider above) where the provider's raw values (breakpoints, components, any `raw` or `inline` path) are the same, so `useTheme().breakpoints.up('md')` gives what it gives below a provider of a client file. Where a raw value differs, the helpers of that member are left out rather than answering from other sizes, and in development the browser warns once for each path: `[umber] The theme of a server ThemeProvider has breakpoints.md = "900px", but the base theme of the client build has "840px": the client build does not have this theme. Register the same theme in a module the client loads, with getEngine().setTheme(theme), createStyle(theme) or configure({ theme }).` A theme with no hidden member is sent and merged as before.
  ([#81](https://github.com/soroush-tech/umber-style/issues/81))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#hidden-members-helpers-on-breakpoints)

### Packaging

- The optional peer dependency `next` of `@umber-style/react/next` is `^16.3.0` (it was `^16.4.6`): the App Router fixture runs on the newest patch of 16.3 and of 16.4 in CI, the whole suite on both tiers (16.3.8 and 16.4.6 when this was released). Before 16.3 the fixture cannot be built with TypeScript 7; built with TypeScript 6 on 16.0.11, the development build of the React it bundles warns at hydration about the nonce of each style element sent in place (the React of 16.1 and 16.2 has the same code, which 16.3 no longer has). The routes of the registry also run on the edge runtime and under partial prerendering on 16.4.6; under partial prerendering a nonce policy does not work (the framework's own scripts of the static shell have no nonce), and the Limits of the docs say what else differs.
  ([#78](https://github.com/soroush-tech/umber-style/issues/78))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#limits)
