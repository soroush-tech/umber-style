## @umber-style/react@0.6.0

Server renders reuse what the render before made (the text of each style element, the sets of `Global`), server components can carry the nonce of each request, and a style function of a server component with no theme says so first.
([#62](https://github.com/soroush-tech/umber-style/issues/62), [#63](https://github.com/soroush-tech/umber-style/issues/63), [#64](https://github.com/soroush-tech/umber-style/issues/64), [#65](https://github.com/soroush-tech/umber-style/issues/65))

### Added

- **`setNonceSource`** (the core's): in the server components build every style element of a request, of a styled component, of `Global` and of a provider, carries the nonce the registered source gives that request. The client build exports it and does not read it.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#server-components-a-nonce-for-each-request)
- A development warning, once for each component, when a style function of the server components build runs with no base theme and no provider yet, before the function runs: it names the component and the ways to give the theme.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#limits)

### Changed

- On a server the text of the style element of a class is made once while the cache holds the class, and `Global` with the same styles and the same theme view takes the sets of the render before, so a function of the theme and the `css` template it returns are not read again. The output is the same.
- The theme below a provider given another object than the base theme is the same object in every render, so `useTheme()` is referentially stable.

### Fixed

- The browser part of a provider of server components threw on a style element that a content security policy refused (it has no sheet), which took the page down.
- A browser cache did not recognise a class whose label has an upper-case letter or a non-ASCII letter (`soroush-Typography-1p2bgvv`) in the style elements of a server: it read the name up to that letter, so after hydration the rule of every such class was written a second time. It reads the name whole now, so a server-rendered page keeps one rule for each class.
- A label with a character that a class name cannot hold (a space, `.`, `:`, `#`, `/`, a quote, `{`) broke the component: a space split the class attribute in two, and the rule's selector was wrong or invalid, so the component got no styles. In the class name a label now keeps `a-z`, `A-Z`, `0-9`, `_` and `-`; white space at its ends is trimmed and every other character becomes `-` (`card.title` is `card-title`, `Card Header` is `Card-Header`), with a development warning once for each such label. A label of those characters only gives the class name it always gave.

### Packaging

- Depends on `@umber-style/core` `^0.6.0`, `@umber-style/is-prop-valid` `^0.6.0` (it was `^0.5.0`).
