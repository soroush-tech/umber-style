## @umber-style/react@0.2.0

The default filter of a string tag is the prop filter of `@umber-style/is-prop-valid/react`, two copies of the binding in one program share their state, and the types of `styled` cost the type checker less.
([#52](https://github.com/soroush-tech/umber-style/issues/52))

### Changed

- A string tag receives by default the props that **`@umber-style/is-prop-valid/react`** is true for, the one list of the attributes of HTML and SVG under React's names, in place of the binding's own list. It is true for every name the earlier list was, and for 124 names more: the older spellings (`class`, `for`, `autofocus`, `fetchpriority`, `innerHTML`, `valueLink`), the SVG font and glyph attributes, legacy HTML attributes (`align`, `bgcolor`, `border`, `cellPadding`, `frameBorder`, `valign`), and the attributes of the `webview` element. Its prefixes are wider too: `data-*` and `aria-*` in any case (`DATA-row`), `x-*`, and `on` followed by any character whose code is below 91 (`on-click`, `on1`, as well as `onClick`). A string tag that is given one of them now writes it to the element. `className`, `style`, `theme` and a replaced `as` stay the component's own. A custom element and a component still receive every prop.
  ([#56](https://github.com/soroush-tech/umber-style/issues/56))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/prop-filters.md#react)
- The props that a function style reads, and the props of a styled component, are the props of the tag with the component's own over them, as before. Where the component's own props name no prop of the tag (`styled(Flex)<{ isOpen: boolean }>`), they are now written as the props of the tag, a type made once for each tag instead of once for each component. Where they share props, the type is computed as before. On a design system with 220 `styled` calls the checker made 29% fewer instantiations and 21% fewer types, used 3% less memory, and its check took 6% less time (TypeScript 7.0.2). The type names, and what compiles and what is an error, are unchanged.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#how-the-cost-of-the-types-is-kept)

### Fixed

- Two copies of the binding in one program, as a server has them when one package is bundled into its build and another is left external, share the default style of each build, the theme contexts of each prefix, the marks of the nearest provider, and the context of `CacheProvider`: a component of one copy reads the theme, the wrapper and the cache of a provider of the other.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/how-it-works.md#two-copies-in-one-program)

### Packaging

- Depends on `@umber-style/core` and `@umber-style/is-prop-valid` `^0.2.0`, declared `workspace:^` (the core was the exact `0.1.0`). Neither is bundled: the filter is a module of its own that an app's bundler includes once, about 4.4 KB minified (2.3 KB gzipped), where the binding's own list was about 3 KB (1.7 KB). A patch of either now reaches this package without a release of its own.
- MINOR: a wider default filter, a new dependency, and the new public API of the core.
- The `react-server` build has no hook and no context, as before.
- Peer dependency: `react` `^19.2.8`, unchanged.
