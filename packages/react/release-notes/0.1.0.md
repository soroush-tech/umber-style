## @umber-style/react@0.1.0

First release. The React binding of UmberStyle: `styled`, `ThemeProvider`, `useTheme`, `StyleSheet`, `useStyle` and `apply` over the engine of `@umber-style/core`, with a server build for server components.
([#9](https://github.com/soroush-tech/umber-style/issues/9))

### Added

- The client build, and a server build that the `react-server` export condition selects. Both have `useTheme`, so a component that reads the theme is written once: in a client component it gives the theme of the nearest provider, and in the server build, where it is a plain function and `readTheme` is another name of it, it gives the base theme (the theme of `createStyle(theme)` or `configure({ theme })`), the same in a full and in a partial render, and an empty object with one warning in development when there is none. A provider of the server build never makes its theme the base theme, and a function theme there is called with the base theme.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/react.md)
- **`keyframes`**, **`globalStyles`** and **`Global`**, in both builds. On a server, `Global` and an animated styled component render `<style href precedence>` elements, and in the browser a `Global` takes over the rules a server page sent.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- The outermost `ThemeProvider` renders no element: its theme is declared on `:root`, and a change of it rewrites that rule without rendering a styled component. A nested provider renders its wrapper. A theme can be a function of the theme above. **`ThemeScope`** and **`useThemeClass`** carry the wrapper of the nearest nested provider to portal content, and **`ThemeContext`** is exported; with no provider, `useTheme` gives the base theme, or an empty object. The server build has none of the three.
  ([#46](https://github.com/soroush-tech/umber-style/issues/46))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/themes.md)
- The outermost `ThemeProvider` is the one with no provider of its engine above it in the page, in both builds. The server build no longer takes the first provider of a request for it: it renders `ProviderScope`, a client component, with the declarations of its theme sent once, and that component chooses the wrapper or the root rule where the tree is whole. A page provider rendered alone by a client-side navigation of the App Router keeps its wrapper under the layout's provider, a provider of either build sees one of the other above it, and `ThemeScope` and `useThemeClass` give the wrapper of a nested provider of the server build. After the root theme changes from the server (a refresh, another root layout), one root rule is live.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#server-components)
- A provider of the server build sends the theme it was given to `ProviderScope` once, as plain data (a function, a symbol or a class instance in it is left out, with one warning in development), and `ProviderScope` makes its rules from those values in the server's render and in the browser alike. It puts the theme, merged over the provider above it in the page or the base theme of the client bundle, into the theme context that every style of its prefix shares: `useTheme()` and function styles of a client component below a provider of a server component read that provider's theme, after a client-side navigation too, and a provider of the client build below one of the server build carries the class of its merged theme again.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#what-crosses-to-the-browser)
- ESM and CommonJS builds with declarations.
- The `'use client'` directive stays on the modules that hold the theme context and on `GlobalRelease` and `ProviderScope`, which the server build imports as references to client components.
- **`css()`**, in both builds and on `createStyle()`: one style made once and passed around, as a sheet entry.
  ([#36](https://github.com/soroush-tech/umber-style/issues/36))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/style-sheets.md)
- The template form of `styled`, `css`, `keyframes` and `globalStyles`, and a styled component as a selector (its `target`, else its class).
  ([#47](https://github.com/soroush-tech/umber-style/issues/47))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md)
- The types apps import: `Theme` (extends the core's), `CreateStyled`, `FilteringStyledOptions`, `PropsOf`, `Interpolation`, and the core's `CSSObject`, `Keyframes`, `SerializedStyles` and `UmberCache`.
  ([#49](https://github.com/soroush-tech/umber-style/issues/49))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md)
- **`CacheProvider`** (client build): `<CacheProvider value={cache}>` gives a subtree its cache, also one whose sheet is in an iframe. Under it every rule the binding writes goes there, and no `<style href precedence>` element is rendered on a server, so a registry is the only output. A component reads it only once a `CacheProvider` has rendered.
  ([#38](https://github.com/soroush-tech/umber-style/issues/38))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/cache-and-server.md)
- A `Global` belongs to the page that renders it. On a server where it renders no style element (`hasServerStyleElements: false`, under a `CacheProvider`) it renders a `<meta name="<prefix>-global">` that names its sets, so that `extractPageStyles` puts them in that page only; the browser renders none, and a hydration skips it. The `Global` of a server component also renders a client component, `GlobalRelease`, which in the browser lets the cache take its rules over and removes them when the page is left in a client-side navigation.
  ([#12](https://github.com/soroush-tech/umber-style/issues/12))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/animations-and-global-styles.md)
- **`CreateStyledComponent`**: what `styled(tag, options)` returns, with the props of the component as type arguments, the type a wrapper of `styled` returns; `StyledFactory` is that type with the props of the tag. A function style reads the props of the tag and those of the type argument, which win, and `theme`, with no annotation. `StyledOptions` takes an optional type argument, the props of the tag, which changes nothing.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#a-wrapper-of-styled)
- The `label` option of `styled(tag, options)`: the label of the class as it is written, over `name` and `slot`. A function style may return a list of styles, nested, merged in order. The tag shorthands are own members of `styled`, so `Object.assign(wrapper, styled)` copies them, and reading one does not use the default style.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md)
- The `theme` of `ThemeProvider` of the default style takes the theme of an app that has not declared its members in `Theme` (an interface of its own, or a function of the theme above that the app types). The theme that `useTheme()` returns is the same object while the theme given and the theme above are, and the theme given itself for an outermost provider with nothing to merge it over.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/typed-styles.md#a-wrapper-of-styled)
- A styled component that wraps a styled component and has a label of its own carries it on its base class and its props class: `styled(Paper, { label: 'Popover' })` is found as `Popover`.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#wrapping-a-styled-component)
- `as` on a styled component made from a component that is not made by `styled` (a function or class component, `forwardRef`, `memo`) is passed to that component as a prop, and the component is always rendered; `as` still replaces a string tag, also at the end of a chain of styled components. Its type is the component's own `as` when it has one. A `shouldForwardProp` you give is used for a component too, not only for a string tag.
  ([#52](https://github.com/soroush-tech/umber-style/issues/52))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#as)

### Packaging

- Depends on `@umber-style/core`, which is not bundled, so every package shares one engine.
- Peer dependency: `react` `^19.2.8`.
