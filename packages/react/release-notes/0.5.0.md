## @umber-style/react@0.5.0

A server render and the browser render the same tree, so that the ids of `useId` agree; and the version that every package of the family carries, with the new range of its dependencies.
([#43](https://github.com/soroush-tech/umber-style/issues/43))

### Fixed

- A component under a styled element given a plain object in `style` got another id from `useId` in the browser than on the server: the browser rendered the `Hold` of the class next to the element, and the server did not. React keeps the attribute of the server, so an `aria-labelledby` or an `htmlFor` could name an id that no element has, with a warning in development. A server now renders an empty place where the browser renders the `Hold`.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#the-server-render-of-a-client-component)
- The same for a server render outside a `CacheProvider` with `hasServerStyleElements` on (the default): the style elements that a styled element and the outermost `ThemeProvider` send in front of their content moved the ids of every component below them. Both now render one place for them on both sides, empty in the browser. The HTML of a server render is the same as before, apart from those ids.
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/server-rendering.md#the-server-render-of-a-client-component)

### Packaging

- Depends on `@umber-style/core` `^0.5.0`, `@umber-style/is-prop-valid` `^0.5.0` (it was `^0.4.0`).
