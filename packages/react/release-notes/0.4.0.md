## @umber-style/react@0.4.0

The state keys of the core in the React binding, for styles that one source shares with React Native.
([#42](https://github.com/soroush-tech/umber-style/issues/42))

### Added

- **`state`**, with the types **`StateName`** and **`StateKey`**, exported from the core: `...at(state('pressed'), { opacity: 0.7 })` in a style is the class and the rules of `'&:active'` written by hand, and so for `hovered` (`&:hover`), `focused` (`&:focus-visible`) and `disabled` (`&:disabled, &[aria-disabled="true"]`). No JavaScript runs for them; server rendering and extraction write the same CSS.
  ([#42](https://github.com/soroush-tech/umber-style/issues/42))
  [docs](https://github.com/soroush-tech/umber-style/blob/main/docs/writing-styles.md#interaction-states)

### Changed

- A style made with `createStyle` (or the default style) adds no style element to the page until its cache writes a rule: under a `CacheProvider`, where every component writes to the provided cache, the style's own cache never makes one, so a style made at the top of a module with no nonce no longer leaves an element without the nonce under a strict content security policy. A style that writes rules of its own (`themeClass` at the top of a module) still makes its element then, with the nonce it was given, or none. ([#13](https://github.com/soroush-tech/umber-style/issues/13))
- Rendering is faster with the core of 0.4.0, with the same markup and CSS ([#10](https://github.com/soroush-tech/umber-style/issues/10)): see the notes of `@umber-style/core@0.4.0`. In the comparison of the work (soroush-bench, one CPU, five rounds, against 0.3.0 from npm): 48 prop-driven elements rendered warm 135 us to 105 us; 48 fixed elements with a fresh cache and the CSS of the page 274 us to 153 us; three nested providers over 48 elements, the same, 475 us to 296 us; the tree of 500 elements the same 2.51 ms to 2.02 ms; the CSS of that page from its HTML 229 us to 127 us.
- In a bundle that writes `production` for `process.env.NODE_ENV`, the development watch of a default style that was never configured (`watchProvidedCaches`) is left out: 0.8 KB less of the binding, minified, in a small app. It warns in development as before.

### Packaging

- Depends on `@umber-style/core` `^0.4.0`, `@umber-style/is-prop-valid` `^0.4.0` (it was `^0.3.0`).
